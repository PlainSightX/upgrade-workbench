# Optuna 3.1.0：真实 ORM 存储开发案例

完整保留177个上游Python模块及包数据；模型可编辑范围仅RDB存储与模型两文件。
采用SQLAlchemy 1.4.54→2.0.38，其他依赖一致。测试面是研究/试验关系数据和版本
登记，不是整个优化框架认证，也不是用户本人构建的优化算法。

9项公开检查＋12项最终检查。真实PG分别检查持久化、关联读取、错误回滚、连接
生命周期及Study ask/tell；每个检查独立schema，每次验证独立数据库。禁外网、
无宿主凭据、无主机端口。锁等待/语句超时是防止坏候选卡死的执行上界。

SOURCE.json逐文件绑定固定提交原字节；上游测试作行为参考，新增检查独立保存。
默认小容量保持不变，本案例需显式大容量配置；不能静默裁去源码。
原文复用同SQLAlchemy版本的已核验官方指南，行为成绩不从APScheduler继承。

当前是否通过及任务结果由工程docs/CURRENT.md和独立结果报告记录，案例存在不等于验收通过。
