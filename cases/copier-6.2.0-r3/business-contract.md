# 本地项目模板生成的行为要求

将完整 Copier 6.2.0 应用迁移到登记的新依赖环境，保留本地项目模板复制的既有行为。
应用读取 YAML 配置，处理默认答案与显式答案，渲染文件名和内容，复制普通文件并生成
答案记录。原来合法的输入仍须合法，原来明确拒绝的输入仍须拒绝。

显式传给 Worker 的 data 保留其值与类型，跳过问题转换。Question 的类型来源与答案
优先级是两回事：未声明类型时，按声明默认值本身的类型推断，不根据 init、last 或
user_defaults 的值重新定义问题类型。默认值为 None 时使用原有 YAML 解释，空字符串
仍是字符串类型。答案查找保持 init、last、user_defaults、声明默认值的既有顺序，
取得的答案按已确定的问题类型转换。声明类型优先，不修改调用者原答案映射。

模板中 to_json 继续支持原有配置、路径及 dataclass 值的编码，并保留调用者指定的
JSON过滤器参数；不能删除原编码能力来绕过依赖导入错误。答案文件仍要求相对路径，
原来可接受的字符串路径继续接受。保留密钥答案记录规则、普通文件字节、排除规则、
跳过已存在文件及预演不写入行为。

本次只使用本地临时模板与输出，不执行远端下载、更新合并、交互终端、模板任务或
Git提交。只允许修改登记的应用Python文件，不改检查、锁、模板或合同。不通过
pydantic.v1兼容命名空间继续使用旧实现。r3是已见开发修订，不增加独立项目数；
新检查结果不覆盖r2历史结果。
