# 本地项目模板生成的行为要求

将完整 Copier 6.2.0 应用迁移到登记的新依赖环境，保留本地项目模板复制流程的既有行为。

使用者指定本地模板目录、输出目录、答案和复制选项。应用读取 YAML 配置，处理默认答案和显式答案，渲染文件名与内容，复制普通文件并按模板生成答案记录。原来合法的路径与答案仍应合法；原来明确拒绝的输入仍需拒绝。操作只接触本次临时模板和输出目录。

显式传入 `data` 的答案优先于默认答案，保留调用方提供的值及类型，不自动进入问题询问和转换流程。没有显式答案时，问题默认值按声明或从默认值推断的类型处理；问题输入过滤器仍执行原有转换，不能转换的数值输入仍不能通过问题验证。这些路径不能合并成“所有答案都会自动转换”。

还需保留相对答案文件路径限制、模板内密钥答案的记录规则、普通文件字节、排除与已存在文件跳过规则，以及预演模式不写文件。用户可选择旧应用已有选项，不因依赖升级增加填写负担或改变输出内容。

本次不调用远端模板下载、项目更新合并、交互终端、模板任务或 Git 提交。问题转换函数的检查不等于完整交互终端验收。不会修改业务需求；遇到必须改变输入接受范围的情况应具体说明。只允许更改登记的应用 Python 文件，不允许改检查、模板、锁和合同。通过兼容命名空间继续运行旧 Pydantic 不算原生新版迁移。
