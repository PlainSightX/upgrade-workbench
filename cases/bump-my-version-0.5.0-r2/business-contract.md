# 版本发布应用的行为要求

本任务保留 `bump-my-version` 0.5.0 的配置、版本计算与文件发布行为。使用者提供当前版本、要提升的版本段及文件规则；应用读取配置，计算新版本，检查目标文件，并按规则更新文件与配置。此任务不运行 Git/Hg 提交、标签或完整命令行交互。

## 必须保持的输入与输出

- INI/TOML 的已有配置内容和配置文件搜索顺序不变。配置更新只修改当前版本，其他文本和格式保持原样。
- 数字版本、非数字发布段、自定义初值、可省略版本段及独立 build 段继续按原规则计算。未知版本段和非法正则仍须拒绝。
- 文件规则及版本段配置中的可选参数可以省略，也接受显式空值；合法的显式值须被保留。主配置的当前版本、标签消息、提交参数、SCM 信息亦保留已有的可省略/空值规则。
- 主配置的序列化格式列表必须提供，不能为空值或空列表。合法格式列表的内容与顺序不改变。
- 一条递归文件匹配规则可以得到多个文件，每个结果使用自身的文件名和该规则的替换设置。展开匹配不得修改调用者传入的规则；没有匹配项时结果为空，不使用文件名作为替代目标。
- 发布只替换指定内容。未匹配文件、同文件中不属于目标的文本、UTF-8 内容，以及配置中的其他行不改变。同一个文件配置的不同版本格式仍分别更新。
- `dry_run=True` 时所有项目文件字节保持原样。写前检查对整组文件完成后才进入写入；任何文件既无搜索值、也无当前版本的原始字符串时，拒绝发布且不写入前面的文件或配置。
- 原实现允许在搜索式未命中时，以存在的当前版本原始字符串进行回退匹配；本任务不把这一行为改成更严格的软件包身份验证。

## 范围

仅允许调整登记的两个应用源文件；依赖锁、检查、业务要求和来源材料不可修改。保留旧输入接受范围，不引入新的业务发布策略。环境变量优先级、所有类型转换、CLI/SCM 全流程及写入途中的自动回滚不属于本次已覆盖的承诺；出现影响这些行为的具体冲突应报告。

生成者使用上述行为要求理解应用。检查及评价技术说明由执行端独立持有，不是生成者可读资料。此要求描述预期，不声明任何候选已经通过。
