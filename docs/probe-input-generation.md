# 有界探针输入生成

本能力只在维护源码中实现，未纳入公开 v0.0.1，也没有成为普通 Agent 的工具或默认策略。
它为已经审定的业务输入域生成可冻结文本语料，再复用现有受审 Docker 探针重放。
输入域、正确行为和探针安全仍需审阅；生成器不能自己决定业务要求。

## 已实现的组件

- `generation.probe_inputs.text_inputs` 复用 Hypothesis 6.142.4，限制字符集、字符串长度和例数。
  实际返回去重语料，不保证任意小输入域都能生成指定数量；将返回值冻结后再运行。
- 输入生成采用 `derandomize=True`、`database=None`、`Phase.generate`，本轮未根据错误反馈
  调整生成器，也没有运行适应性 shrinking。复现以冻结语料为准，不承诺换版本仍生成相同序列。
- `smallest_recorded_counterexample` 只在已执行且记录为 `different` 的输入中，按规范 JSON
  的 UTF-8 字节长度、再按字节序选择一条。它不是整个输入空间的最小反例。
- [统一读数与旧版比较](probe-comparisons.md) 将同一具体输入在旧源码/旧依赖与候选/新依赖
  上的输出并列呈现，严格区分 `same`、`different`、`incomplete`。这是调查证据，不是独立验收。

## 使用边界

`probe-generation` 是可选 extra。只有环境负责人在选定并登记的开发环境中安装；
不得为了本组件同步已有服务环境。普通单测不要求这个 extra，真实生成检查在缺依赖时
单项跳过，其余输入域、缺依赖报错和反例选择检查仍执行。

在具有锁定 extra 的环境中，可生成并保留语料：

```python
from upgrade_workbench.generation.probe_inputs import text_inputs

values = text_inputs(alphabet="abcXYZ09:_ -'", max_length=12, max_examples=24)
```

生成字符串本身不执行目标代码。把语料放入探针后，仍须走 `propose_probe`、安全审阅和
`run_probe` 的 reviewed-snapshot Docker 路径，不得直接在宿主导入第三方目标库。
记录上限仍为 2048 UTF-8 字节、深度 6、128 个节点；应按实际输出分批，超限只得到
不完整证据，不能截断后声称相同。字符集和数量的上限不保证最终输出一定容纳得下。

## 首次组件结果（2026-10-05）

实验载体为已见的 csvsql SQLAlchemy 迁移案例。以现有公开驱动执行补丁作为正确对照，
分别只将 `query`、`before-insert`、`after-insert` 的调用改成 `execute(text(query))`，
构成三个同类、人工定义的错误变体。它们不是三个新迁移任务，也不是模型自主发现的风险。

运行前固定上述变体、正确对照、输入域、语料、顺序及预算。每份探针在旧环境、
直接升级环境和候选环境中执行；每个位置只与该位置的错误变体及正确对照比较。
普通历史输入为 `ready:ok`，已有有效历史输入为 `:tagged`，生成语料含 24 条、每批 8 条。

| 路线 | 每个位置的输入数 | 检出错误变体 | 正确对照出现差异的位置 | 不完整输入比较 |
| --- | --- | --- | --- | --- |
| 普通历史输入 | 1 | 0/3 | 0/3 | 0 |
| 已有有效历史输入 | 1 | 3/3 | 0/3 | 0 |
| Hypothesis 生成语料 | 24 | 3/3 | 0/3 | 0 |

生成语料在三个错误位置各只有 `c_-:09` 这一条出现差异：旧版返回完整字符串，
错误候选得到 `StatementError`；正确对照仍返回原值。其余 23 条没有区分这类错误。
这说明任意包含冒号的字符串不一定有效，不能把输入数量当作覆盖充分性。
该字符串是本轮已执行语料中的最小差异输入，不是经 shrinking 找到的全局最小反例。

30 份有效报告共执行 90 个 Docker 阶段。以下耗时为报告中阶段时长的累加，
环境准备时长另计；不是端到端交付、人工节省或模型运行耗时。

| 路线 | 报告 / 阶段数 | 具体输入阶段执行数 | 阶段时长合计（秒） | 环境准备合计（秒） |
| --- | --- | --- | --- | --- |
| 普通历史输入 | 6 / 18 | 18 | 65.938 | 10.064 |
| 已有有效历史输入 | 6 / 18 | 18 | 64.907 | 10.045 |
| 生成语料 | 18 / 54 | 432 | 199.092 | 30.671 |

输入数与批次成本不同，不能称为等预算性能比较。正确对照共 78 次输入比较无差异，
但不据此推断其他业务域的误报率。本轮模型请求为零，不产生 API 成本或任务成功率证据。

## 执行缺陷与结果有效性

第一次部分执行的 CSV 文件名是 `items_<index>.csv`，SQL 却使用 `FROM items`，
导致旧环境也出现 `OperationalError`。这是实验夹具错误，不是 Agent 或生成算法失败。
原报告保留但不计入上表。修正为独立输入目录下的固定 `items.csv`，重新登记探针模板身份；
字符域、冻结语料、变体、顺序和预算均未改变。

修正后每份报告必须有正确旧版参照，否则立即停止。分析再次读取完整实际 stdout、
核对报告 hash、冻结源码和完整矩阵，再重算输入/输出差异；不能仅根据 pytest 通过计数判断。
完整冻结对象、首次失败、有效报告及资源归档由本轮私有工作包保存，不公开自由日志或运行环境。

## 采用决定与后续

**采用统一读数与绑定旧版参照，保留生成器供有界组件调查；暂缓普通 Agent 自动触发。**
生成语料补上了普通单输入的盲区，但没有超过已有有效单输入，且用了更多执行资源。
本结果不支持“自动风险发现”“优于有效探针”“降低模型费用”或“提高迁移成功率”。

本轮原后续是选一个不同语义风险域，预先定义合法输入和业务依据，再比较合理的定向边界样例
与生成语料；不得拿这三个已知变体继续调参追求正结果。只有出现足够的新增发现，
才考虑接入 Agent 的选择/运行/消费链，并观察它是否真正改变调查或修复。
普通工具消费与未见任务评估仍保留为后续工作，未因本轮暂缓而取消。

## 后续 A1：有限可选值分区

[可选值语义 A1](results/semantic-boundaries-a1/README.md) 已完成上述新风险域调查。
在 bump-my-version 的两个字段上，用有限笛卡尔积枚举省略、空值、合法值三种状态；
不添加依赖，也不将私有枚举脚本包装成已实现的普通 Agent 生成工具。
定向 7 条和穷举 9 条各检出三个受控变体，正确对照均无差异，报告/阶段数相同。
穷举没有新增检出，所以仍暂缓自动生成；这不是 Hypothesis 状态机或 shrinking 实验。

本次普通 v2 任务自主设计了定向 glob 和配置探针，结构化旧版比较确实进入后继请求，
模型也引用了具体结果。但未使用自动生成器，候选验收与 v1 同样为 43/43，
不能据此声明生成器提高了修复成功率。该观察补了诊断消费，不补造生成收益。
首次固定序列与合法初值冲突的夹具结果独立保留；校正发生在模型请求之前。
