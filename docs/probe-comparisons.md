# 受审探针的候选比较

当前维护源码提供可选 `semantic-risk-v2`，尚未纳入已发布的 v0.0.1。
它沿用原来的探针审阅、Docker 执行、候选快照及独立验收，只补充结构化读数和比较。
没有新角色、开放 shell、自动安全批准或强制退出条件；默认不启用。

## 使用

在普通任务 profile 中设置：

```json
{"semantic_risk_policy": "semantic-risk-v2"}
```

适用于协议 4、5、6 的 Solver。已有 v1 配置保持原行为；继续旧冻结任务仍须使用原实现。
模型通过现有 `propose_probe` / `run_probe` 提交和运行探针。需要比较时，在收集到的
测试函数中执行实际操作后，打印一条独立记录，前面换行以避开 pytest 进度文字：

```python
print("\nUPGRADE_WORKBENCH_PROBE_SAMPLE:" + json.dumps({
    "input": actual_input,
    "output": observed_output,
    "path_completed": True,
}))
```

v2 的维护提示要求从源码和业务合同划分省略参数、显式空值、合法值及相关非法/集合边界，
并记录实际结果，不能把“可空”当作“可省略”。先使用合理定向样例；有限输入域可以穷举，
但没有新增检出时不自动扩大。导入和初始化失败不得作为普通输入拒绝计入。
这是通用调查指导，不是自动生成器、案例规则或新增验收门槛。

记录上限为 2048 UTF-8 字节，支持有限 JSON 对象、数组和标量。记录实际输入及观察值，
不要填预计值。被研究的预期业务异常可以作为输出；导入、fixture 或初始化失败不属于
已完成业务路径。`path_completed` 由探针声明，其真实含义仍需与源码核对。

## 比较结果

Solver 的 `diagnostic_state.probe_comparisons` 自动显示最近最多四次有限比较：

| 结果 | 可以说明什么 |
| --- | --- |
| `same` | 所记输入没有区分这两个已执行源码 |
| `different` | 所记输入的观测确有不同；哪一个正确仍由合同与独立验收判断 |
| `incomplete` | 缺读数、未完成执行、不同输入或身份不可比，不能判断相同或不同 |

`direct_upgrade_vs_candidate` 比较直接升级源码与候选，不是两种修复方案。
同一探针在两个候选上实际运行后，才形成 `candidate_vs_candidate`。探针代码、案例、
新依赖锁、实际环境镜像及所记输入必须可比；相同补丁不能因修订元数据不同冒充另一实现。
每项绑定观察 ID、源码修订与补丁 hash；`right_is_current_source` 标识右侧是否仍为当前源码。
历史执行可以作为具名参照，不自动证明后续源码。隐藏观察不参与公开比较。

结果来自已校验收据及完整 stdout，不从终端片段或 pytest 绿灯猜测。没有结构化记录的
旧探针保持原有范围，不补造历史读数。一次差异、相同值及模型解释均不能替代独立验收，
也不要求模型制造错误候选或额外差异才能结束任务。

## 统一测量与旧版参照（维护增量）

当探针既使用数值判据又需要比较具体输出时，在原测量中同时打印 `input` 和 `output`，
不用为同一次操作再打印第二条样本记录：

```python
print("\nUPGRADE_WORKBENCH_MEASUREMENT:" + json.dumps({
    "before": before_count,
    "after": after_count,
    "path_completed": True,
    "input": actual_input,
    "output": observed_output,
}))
```

两个具体字段须同时提供，并与独立样本共用有限 JSON 校验。统一记录也受 2048 UTF-8 字节
限制；传统纯数值记录保留原限制且不会被推测为具体样本。重复具体记录产生歧义，
无效统一记录不能让数值验收判为成功。

新 `old_original_vs_candidate` 对同一探针、同一具体输入，比较原源码/旧依赖与候选/新依赖。
它绑定受审报告中规定的两份依赖锁、实际环境镜像及相同基础镜像；身份缺失、读数缺失、
执行未通过或输入不同均标为 `incomplete`。旧报告缺少绑定时不补造旧环境证据。
原有同环境比较仍要求相同新锁和镜像，不能用这个新入口放宽其校验。

旧行为只能作为要求保持兼容的行为参照；官方规定改变的行为须按新合同判断。
两版本输出有差异不自动证明候选错误，输出相同也不证明语义等价。
Solver 请求投影的调用者单测已覆盖有效统一记录与旧版比较，不等于真实模型消费实验。
有界输入生成的首轮组件结果、正确对照和较强单输入基线见
[输入生成](probe-input-generation.md)；普通 Agent 的自动输入生成尚未接入。

## 依据与当前边界

此前 [csvsql 比较](joint-r2-agent.md) 中，正确补丁仍把不具区分性的输入解释成区分证据。
本轮复用现有执行与测量机制，使这种有限结论直接进入 Solver 请求；未采用新框架或增加角色。
输入分区的参考思路见 [Hypothesis 官方教程](https://hypothesis.readthedocs.io/en/latest/tutorial/introduction.html)。
目前这是一项可选诊断能力，质量与费用收益需要冻结的模型运行证据，不由字段或测试数量推出。

## 本轮结果与采用决定（2026-10-05）

本轮先用两个手工候选校准接口，再冻结一个已见 csvsql 任务的 v1/v2 成对比较。
使用同一 `deepseek-flash`、原始源码、版本资料、工具、执行环境、预算和独立验收；
没有种子候选，顺序固定为 v1 后 v2。两臂首次终态都冻结后才运行独立验收，
维护侧仅审阅完整补丁与探针的执行安全，没有答案提示、手改候选或验收反馈回流。

| 项目 | v1 | v2 |
| --- | --- | --- |
| 首次终态 / 独立结果 | submitted / candidate_verified | submitted / candidate_verified |
| 旧版 / 直接升级 / 候选 | 6/6、0/6、6/6 | 6/6、0/6、6/6 |
| 模型请求 | 8 | 5 |
| 输入 / 输出 token | 320,959 / 127,185 | 172,691 / 81,574 |
| 登记价格估费（USD） | 0.248912 | 0.149699 |
| 候选修订 / 维护安全审阅 | 2 / 6 | 1 / 2 |

两份最终补丁字节相同。安全审阅由 Codex 完成，不是用户人工操作或已测人工分钟。
估费使用 2026-09-26 登记的每百万输入/输出 0.30/1.20 USD，不是当前报价或实际账单；
13 次调用都有用量记录并已在本地账本结算。API 记录耗时分别约 546 / 340 秒，
不包含全部 Docker、审阅、中断等待，不能写成端到端交付时长或人工节省。

**实际下游结果并不支持新比较机制的任务收益：**

- 手工 Docker 校准中，`ready:ok` 在 `text(query)` 与驱动执行上读数相同；
  `:marker` 的读数不同。四份实际报告经过当前解析器核对。这只证明接口能区分这些测量，
  不是模型自主调查、修复或泛化成绩。
- v1 先生成 `text()` 补丁，自行用 `':tagged'` 探针发现解释差异，修订为驱动执行，
  然后复跑同一探针并补查提交可见性。没有重复此前的 `ready:ok` 区分性误判。
- v2 第一份补丁就选择驱动执行，发生在任何比较读数产生之前。它只生成原有数值判据，
  未打印新格式样本；第 5 次真实请求收到一条具名 `incomplete`，不是 `same` 或 `different`。
  终态把冒号语义明确写为版本/源码推断，未声称已经实测。
- 没有观察到模型利用有效比较改变诊断或候选。因此不能把 8→5 或估费差异归因于比较器，
  也不能据此声称稳定收益、成功率提升或整套 Agent 优于简单工具 Agent。

**决定：保留经校准的可选测量接口，暂缓将 v2 升为推荐或默认配置。**
有效读数的模型消费与具体改进这一事前转移条件没有满足，FastAPI 条件对照未启动。
不强迫模型制造错误候选、不加结束门槛、不为得到正结果重复这个案例。
后续只有真实任务需要比较两份已有候选时再使用；当前样本不作为简历效率收益。

聚焦接口/诊断检查 142 项、任务及生成调用者回归 76 项通过；这些是实现验证，
不替代以上任务结果。首次策略读取错误及分析辅助脚本的输入/输出身份混淆均保留在
本轮私有工作包中，修正后重新核对，未修改历史报告。完整请求、补丁、账本、
执行报告及冻结对象私下留存，不把自由日志或模型完整回复作为公开材料。

## 后续 A1：有效旧版比较已被消费

[可选值语义 A1](results/semantic-boundaries-a1/README.md) 在已见 bump-my-version 真实应用上，
验证了另一个输入风险域。定向 7 条与穷举 9 条都检出三个受控错误，没有新增生成优势。
随后同条件单次 v1/v2 任务首次终态均 submitted，完整独立结果均 candidate_verified，
旧版与候选均 43/43；直接升级为导入失败，不冒充已完成行为观察。

v2 自主记录 glob 与可选配置探针；第 7–10 次真实请求消费有效旧版 `same`，
后继动作和终态明确引用实际测量。相应直接升级比较仍为 `incomplete`。
这补上了此前有效比较没有真实消费的证据缺口；候选在读数产生前已经生成，未因此修订。
两臂请求 12/10、估费 0.476354/0.406627 USD，仅作已见单次观察，不宣称质量或稳定降本。
有效消费成立不等于推荐条件全部满足，v2 继续可选，默认不变；不重写上方首次负结果。
