# 版本文档检索：BM25、向量与 RRF 混合的排序对照

2026-09-16。对象是 Pydantic 2.11.7 官方迁移原文（38 个父节、56 个子块）。
16 条开发查询在第一次排序前登记：6 条具名 API、6 条英文语义、4 条中文语义，
每条标注一个目标章节。CPU FP32、固定模型版本；没有在看到结果后修改标注或删除不利查询。

| 策略 | 目标章节排第一 | 目标章节进入前五 | MRR@5 |
| --- | ---: | ---: | ---: |
| BM25 | 10/16 | 11/16 | 0.6458 |
| BGE-M3 dense | 11/16 | 14/16 | 0.7708 |
| BM25 + dense + RRF | **13/16** | **15/16** | **0.8750** |
| RRF + reranker | 11/16 | **16/16** | 0.8094 |

- 具名 API：BM25 与混合都是 6/6 首位，纯向量 4/6。`__get_validators__` 在纯向量前五之外，混合后回到第一。
- 中文查询：BM25 前五 0/4；混合 3/4，首位 2/4；重排补齐到 4/4 前五。
- 重排能补回中文问题，但会把另一些正确的首位结果往后挤，所以没有设成默认。

**取舍：** 提供混合模式；重排按需开启；普通任务默认仍用 BM25。任务中的自动查询主要来自源码符号，
这部分 BM25 已经足够好；是否改默认，要看真实修复任务的质量与开销，而不是这一组开发查询。

实现：`retrieval.py`（BM25 / dense / RRF / 重排）、`semantic.py`（子块与父节）、`evidence.py`（按依赖版本取原文）。
同一子块上分别排序后用 RRF 按名次融合，不直接相加不同尺度的分数。

## 局限

这是 16 条开发查询，不是独立留出集，也不是召回率或迁移成功率。初版探针复用编码缓存、计时分辨率不足，
所以不据此比较各策略耗时。
