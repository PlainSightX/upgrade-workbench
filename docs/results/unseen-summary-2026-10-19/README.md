样本只有 4 个，每个只运行一次，没有对照臂。这**不是成功率**，也不能说明工作台优于裸模型、
其他 Agent 或人工。它说明的是：在这 4 个事先冻结检查的案例上，同一配置的普通任务流程各跑一次，
最终候选都通过了模型看不到的独立验收。

## 方法

- 选择标准：本工作台 `cases/`、`docs/`、`tools/`、`src/` 中没有出现过；许可宽松（MIT、Apache-2.0）；
  库源码约 400 至 1,100 行；固定在上游自己迁移之前的标签；直接升级有真实的接口断裂。
- 每个案例在任何模型请求之前冻结业务合同、结构化条目和两组检查的哈希，再做 Docker 准入：
  旧依赖必须全过，直接升级必须失败。之后封存清单、创建任务。第一次模型请求之后检查没有改过。
- 公开反馈检查（每案 6 项）在修复中可见，独立验收检查（11 至 13 项）只在任务终态后运行。
- 维护者只审阅执行边界（修改范围、无文件/网络/进程越权、未改检查），不提示根因或修法，
  不反馈独立验收结果。四次运行共批准 11 个候选、接受 22 次诊断，没有拒绝。

## 各案例要点

- **sqlalchemy-mixins：** 字符串关系名不再被预加载选项接受。r2 公开 6/6，但事后回放只有 17/19；
  Auditor 疑问加 Agent 探针促成 r3，才达到 19/19。这是四个案例中唯一一次过程中的追加修改改变了验收结果。
- **pydantic-cli：** `ModelField` 删除，导入即失败。r1 已满足全部检查（事后回放 17/17），之后三次修订
  处理检查之外的路径，其中一次把原始版本子命令 `--help` 的非零退出码改成 0，这超出了“保持旧行为”。
  Agent 没有给出退出声明，用完 24 次调用被截停。
- **Flask-Pydantic：** `FieldInfo.is_complex` 删除，查询路径全部 500。Auditor 两次指出边界输入，
  Agent 修了两次；事后回放显示 r1 在本组检查上已经 17/17，后两次修改本组检查无法区分。
- **sqlalchemy-filters：** 混合属性的 `extension_type` 变成枚举、私有属性 `_legacy_setup_joins` 删除。
  13 次请求、一个候选即通过，是四个案例中最便宜的一次。

## 失败与不足

四个案例都通过了独立验收，没有验收失败可分析。过程中的问题如下，按严重程度排列：

1. **检查区分力有限。** 三个案例中，较早的修订在事后回放时也能通过全部检查（pydantic-cli r1、
   Flask-Pydantic r1，sqlalchemy-filters 只有一个修订）。只有 sqlalchemy-mixins 的检查挡住了中间修订。
   独立验收通过只说明满足了这组检查，不说明后续修改没有引入检查之外的行为变化。
2. **退出判断。** pydantic-cli 没有主动结束，24 次调用中有一部分用于检查覆盖之外的调查，
   并且修改了合同没有登记的原始行为。sqlalchemy-mixins 也在第 24 次请求时才提交。
   调用上限更低时，两者的过程都会不同。
3. **编写期修正。** 三个新案例在冻结前都按旧环境试运行修正过检查：
   pydantic-cli 1 处、Flask-Pydantic 1 处导入写法、sqlalchemy-filters 2 处。这些修正发生在任何模型请求之前，
   理由写在各案例 README 中，但说明维护者编写的检查第一次就有错误，oracle 的独立性有限。
4. **预训练污染。** Flask-Pydantic（2024-01）和 pydantic-cli（2024-08）的上游修复已公开，
   sqlalchemy-mixins 的上游修复发布于 2023-03；模型可能见过。sqlalchemy-filters 没有上游官方修复，
   但可能存在第三方补丁。本批结果无法区分推理和回忆。

## 不能得出的结论

- 不能说成功率是 100%，也不能给出置信区间意义上的估计；n=4，每个案例一次。
- 不能说优于裸模型、其他 Agent 或人工；本批没有对照臂。
- 不能外推到更大的仓库、PostgreSQL / MySQL 方言、异步接口或其他依赖家族。
- 人工审阅时间没有测量；“创建至独立验收”的分钟数包含审阅等待和 Docker 时间。

## 复核

每个案例目录下的 README 给出无需模型 API 的 `inspect` 和 `verify` 命令。新案例的获取、冻结、准入和
封存脚本是 `tools/dev/acquire_unseen_batch_cases.py`；sqlalchemy-mixins 使用
`tools/dev/acquire_sqlalchemy_mixins_case.py`。原始任务、请求轨迹和准入日志没有公开。
