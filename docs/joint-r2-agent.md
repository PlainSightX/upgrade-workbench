# 版本语义自查与实际迁移比较

本轮只评估一个可选机制 `semantic-risk-v1`：让 Solver 在选择替换API时区分接收者、
调用链及新旧输入解释方式，并在结束前说明已测输入与未测风险。它复用现有原文、
源码和探针工具，不新增角色、验收权限、强制调用或退出门禁，默认配置保持不启用。
源码在 `generation/semantic_risk.py`；配置通过任务协议、请求收据和发送校验冻结。

## 为什么选择这个改动

此前一次csvsql任务的完整可修改文件和官方依据都已送达。结束说明却混淆
`Connection.execute(str)` 与 `Session.execute(str)`，并从插入后的行数正确推断全部
SQL输入语义已保持。候选公开反馈通过，最终六项检查只过四项。
这是语义综合与测量范围的缺口，现有证据不支持归因于缺少源码或Docker失效。

参考SQLAlchemy的固定版本[迁移说明](https://raw.githubusercontent.com/sqlalchemy/sqlalchemy/rel_2_0_25/doc/build/changelog/migration_20.rst)
及Hypothesis的[测试教程](https://hypothesis.readthedocs.io/en/latest/tutorial/introduction.html)，
采用“输入分区与差分观测”的思路：两个实现都能通过普通路径时，选择一个可区分
语义的测量，断言真实值或外部效果。没有引入Hypothesis依赖，也没有自动生成测试框架。
旧行为仅在合同要求保持时作为参照；有意变更需要明确取舍。

此前只读Auditor扩编没有可归因收益且出现误报，因此本轮不恢复那份提示、
不扩大多Agent、不新增按案例ID选择答案的规则。

## 冻结比较

csvsql是已见开发案例，每臂仅一次，顺序为当前配置→可选机制。
模型、资料、源码、可读工具和预算相同：`deepseek-flash`、thinking enabled、P4、
最多16次请求、公开执行准备600秒/测试240秒、focused正文96,000字节、
库存64,000字节。不提供官方codemod初始补丁；供应商未提供随机种子参数，
“无种子补丁”不代表采样可确定复现。

每次补丁/探针由人读取完整内容后只审执行范围与安全，不提供业务答案或手改候选。
两臂首次终态与候选共同冻结后，才运行最终检查；独立验收结果不回流给模型。
比较记录终态、通过项、语义解释、区分性测量、请求/token/估费、执行时间及人工介入。
增加一张风险表或更多文字本身不算收益。

条件转移在首次请求前登记：只有候选得分提高，或错误接收者推断纠正且出现基线缺少的
有效区分性测量时，才最多准入一个现有迁移任务并运行一次成对比较。
候选固定先FastAPI必填列表、再SQLAlchemy-Continuum；每项只跑一次旧/直升反馈，
遇到第一个合格即停止，不替换负结果，不重跑到成功。它们是未按新机制调优的已见任务，
不能称陌生仓库基准。

## 结果与采用决定

csvsql首次比较已完成，两臂均正常提交；共同终态冻结后才运行最终检查：

| 指标 | 当前配置 | 可选机制 |
| --- | --- | --- |
| 旧版 / 直升 / 候选 | 6/6、0/6、4/6 | 6/6、0/6、6/6 |
| 独立结果 | `candidate_not_accepted` | `candidate_verified` |
| 模型请求 | 4 | 7 |
| 输入 / 输出token | 146,925 / 36,772 | 285,843 / 115,188 |
| 估算USD | 0.088206 | 0.223981 |
| provider调用累计秒 | 152.625 | 482.608 |
| 补丁 / 诊断人工安全审阅 | 1 / 2 | 2 / 3 |

模型在第3次请求自行重读语义、选择 `exec_driver_sql()`，没有独立失败反馈、人工答案提示或
手改候选。观察到本次候选质量提高，同时调用、token和估费增加。费率按登记的输入0.30/
输出1.20 USD每百万token计算，不是实际账单；provider累计时间不包含全部执行、排队和人工
审阅等待，完整任务墙钟也受本轮人工工作顺序影响，不能用来宣称人工节时。

**测量仍有缺口。** 改进臂提出了冒号输入探针，但 `ready:ok` 和 `10:30:00` 的冒号前
都是词字符。终态后的独立SQLAlchemy 2.0.25检查确认：这两个值在 `text()` 中不形成绑定，
与驱动执行得到相同值；`':marker'` 才形成命名绑定并出现差异。因此原探针可证明所测值与
持久性，不能证明它宣称的实现区分能力。最后解释也保留这一错误，未向模型回灌纠正。
正确补丁与探针充分性分开判断，不把绿色探针当作全语义证明。

预登记的得分提高条件成立，按原排序准入FastAPI必填列表任务：公开旧2/2、直升1/2，
无收集/设置错误或跳过。随后仅执行一次成对转移，两个首次终态都是正常提交：

| 指标 | 当前配置 | 可选机制 |
| --- | --- | --- |
| 旧版 / 直升 / 候选 | 4/4、2/4、4/4 | 4/4、2/4、4/4 |
| 独立结果 | `candidate_verified` | `candidate_verified` |
| 模型请求 | 12 | 16 |
| 输入 / 输出token | 750,240 / 178,901 | 1,009,487 / 258,861 |
| 估算USD | 0.439757 | 0.613486 |
| provider调用累计秒 | 738.266 | 1,030.654 |
| 补丁 / 诊断人工安全审阅 | 1 / 3 | 1 / 3 |

两臂自行定位必填列表缺省值被传入Pydantic 2校验、随后错误编码触发500的路径，
在查询参数提取处恢复“缺少必填值”的判断。最终四项为公开两项、独立两项；
公开与独立端点、列表类型和输入不同，但仍是同一迁移行为，不能扩大为全部FastAPI兼容。
自选探针记录局部ASGI请求与错误栈，明确为观察性测量，不能以其pytest退出码作为业务验收。
没有将隐藏结果返回模型，也没有重跑或替换转移任务。

**采用决定：有限可选，默认不启用。** csvsql观察到候选质量改善；转移任务未观察到
新增质量收益，调用与估费继续增加。可在需要显式语义调查的任务中选择该机制，
必须保留人工安全审阅和独立验收。一次随机采样比较不能证明通用因果、稳定性或成本优势，
也不能证明自选探针充分。本固定批次到此结束，不继续调提示或追加比较。

[精选结构化结果](examples/semantic-risk/result.json)保留四个首次任务的候选、检查、
用量与原报告哈希，以及探针反例和采用决定。它不分发完整转移输入或原始模型轨迹；
公开可执行复验仍是csvsql固定正确候选，不把结果JSON称为全部对照的复现包。

固定正确候选的复验和历史失败仍见[csvsql案例](examples/csvsql/README.md)；
此前整套工作台的正反收益见[历史比较](examples/comparison/README.md)。

## 使用和CI边界

普通用户从[安装说明](public-install.md)选择固定候选、CLI或服务路线。
本机制通过profile的 `semantic_risk_policy` 配置，适用于协议4/5/6的Solver；
不改变人工审阅和独立验收职责，不自动影响Investigator或Auditor。
当前不建议凭单次开发比较启用为通用默认。

[CI说明](public-tests.md)区分自动单测、手动默认分支的零模型固定补丁Docker复验与
本轮真实模型实验。远端CI尚未执行；固定补丁通过不能证明新提示改善生成质量。
精选公开报告不包含模型原文、机器路径、账本、凭据和大量容器日志。
